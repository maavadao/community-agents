# 🌱 Rules

**✍️ Author:** Muhammad Rehman Tanoli

Rules for everyone who builds, reviews or maintains agents in **maava-Community-Agents**. Humans and AI coding assistants alike. 🤝

---

## 🎯 Mission

maava Community Agents are open-source AI agents for sales, marketing and growth. We don't build from scratch: we take proven open-source agent repos, make them better for businesses, and customise them for each one. 📚💛

This repo is the index of those agents; each agent lives in its own repo. Every agent is free for education, free to read and free to improve. When an agent earns money, **60% rewards the developer community who built it** and **40% goes to Maava Charity** to educate deserving children, orphans and street children.

Every rule below serves that mission. If a rule is unclear, choose the option that is safest for children and most open to the community. 🧒🌍

---

## 💎 1. Core principles

1. 🛡️ **Children first.** Safety and safeguarding come before features, speed and cleverness.
2. 🎓 **Education purpose.** Agents exist to teach, learn, research or inform. No other use belongs here.
3. 🆓 **Open and free.** No listing fees, no creation fees, no commissions. Code stays open under Apache-2.0.
4. 🤝 **Built together.** Contributions are welcome from developers, educators, designers, translators and subject experts, and every contribution is credited.
5. ✅ **Accuracy over fluency.** A confident wrong answer is worse than "I don't know".
6. 🌈 **Inclusive by default.** Agents must work across languages, abilities, low-cost devices and low-bandwidth connections.

---

## 🗂️ 2. Repository structure

- 📁 Each agent lives in its own repo, included in this index as a Git submodule at `agents/<agent-name>/`.
- Every agent repo contains:
  - 🐍 its code,
  - 📖 a `README.md`,
  - 📝 an `agent.yaml` describing the agent,
  - 🪪 a `LICENSE` (Apache-2.0).
- 🧩 Start new agents by copying `template/`.
- Folder names under `agents/` are lowercase, hyphen-separated and unique. Nothing but submodules goes there.
- 🔄 Submodules are moved to each agent's latest commit daily by the Update agents workflow. Don't bump them by hand unless a maintainer asks.
- 🧰 Shared tooling lives in `sdk/` (`maava-agent-sdk`) and `scripts/`. Do not duplicate it inside an agent.
- 📚 Docs live in `docs/`. ⚙️ CI config lives in `.github/`.
- 🚫 Never edit `index.json`. It is generated by `scripts/build_index.py` on every merge to `main`.

---

## 📝 3. agent.yaml requirements

- ✔️ Must be valid and complete, with no placeholder values left over from the template.
- 🎯 Must state the agent's purpose, intended audience and age range, languages supported, and author(s).
- 🔐 Must state what data the agent collects, or explicitly say it collects none.
- 🔗 `links.repository` is set to the agent's repo by the index; don't point it anywhere else.
- 🔄 Must be updated whenever behaviour, data handling or version changes.

---

## 🧒 4. Safeguarding and content (mandatory)

Agents that may be used by children must meet these before they are merged or listed.

- 🎂 **Age suitability.** Declare the intended age range. Content, tone and vocabulary must fit it.
- 🚷 **No harmful content.** No sexual content, graphic violence, self-harm instructions, hate, harassment, or content that exploits or grooms.
- 🧠 **No manipulation.** No dark patterns, manufactured urgency, emotional dependency, advertising aimed at children, or attempts to move a child off-platform.
- 🆘 **Safe escalation.** If a learner signals distress, abuse or danger, the agent must respond with care and point to a trusted adult or local help. It must never try to handle the situation alone.
- 🤖 **No identity claims.** An agent must be clear that it is an AI. It must never pose as a teacher, doctor, relative or other real person.
- 🩺 **Specialist subjects.** Medicine, law, mental health and similar areas need review by a qualified educator or expert, and the agent must say it is not a substitute for professional help.
- 🧼 **Content filtering.** Agents must work with the runtime's content filtering and never disable or bypass it.

---

## 🔒 5. Privacy and data

- 🪶 **Minimise.** Collect only what the agent needs to work. Prefer collecting nothing.
- 🙅 **Children's data is never sold, shared for advertising, or used for profiling.**
- 🕵️ **No PII in logs, metering or analytics.** Usage metering must not contain personal data.
- 🔑 **No secrets in the repo.** No API keys, tokens, passwords or private keys in code, config, examples, tests or history. Use environment variables and document them in the README.
- 🌐 **Third parties.** Do not send learner data to third-party services unless it is declared in `agent.yaml` and approved in review.
- 🚨 If you find leaked data or a vulnerability, do not open a public issue. Report it privately to the maintainers and rotate any exposed credential immediately.

---

## ⚖️ 6. Fairness and inclusion

- 🔍 Test for bias across gender, region, religion, caste, language, disability and economic background.
- 🗣️ Support local languages wherever possible, and say clearly which languages are supported and how well.
- 📱 Keep it lightweight: work on low-cost devices and limited bandwidth. Avoid heavy dependencies and large downloads unless essential.
- 🌾 Do not assume reliable internet, a personal device, or high literacy.

---

## 🧑‍💻 7. Code quality

- 🐍 Python is the default language. Follow PEP 8 and format with the project's configured formatter.
- 🏷️ Add type hints to public functions.
- 📌 Pin dependencies in `requirements.txt` and add only what you use. Check licences are Apache-2.0 compatible.
- 🧯 Handle errors explicitly. Never swallow exceptions silently, and never expose stack traces or internals to learners.
- 🧪 Write tests for agent behaviour, including safety cases (refusals, escalation, off-topic and adversarial prompts).
- 🔌 Use the `maava-agent-sdk` for talking to a maava gateway rather than custom clients.
- 💬 Keep prompts and system instructions in readable, reviewable files, not buried in code.
- 👀 No obfuscated, minified or binary-only code. Everything must be readable.

---

## 🔎 8. Accuracy and transparency

- 📖 Educational content must be correct, current and sourced where possible.
- 🤔 Agents should say when they are unsure, and should not invent facts, quotes, citations or statistics.
- ⚠️ Document known limitations in the agent's README.
- ©️ Do not copy copyrighted material you have no right to use. Credit sources and respect licences.

---

## 🔀 9. Contribution workflow

1. 📘 Read `CONTRIBUTING.md` and `docs/getting-started.md`.
2. 🛠️ To improve an agent, fork **its repo**, create a branch (`fix/<short-description>`) and open the pull request there.
3. 🧩 To add an agent, build it in its own repo from `template/`, then fork this index and add it as a submodule on a `feat/<agent-name>` branch.
4. 📝 Fill in `agent.yaml` and the README.
5. 🧪 Run validation and tests locally.
6. 🚀 Open a pull request describing purpose, audience, data handling and testing.
7. 💬 Respond to review feedback. Maintainers and community reviewers may request changes or reject an agent on safety grounds.

Pull request rules:

- 🎯 One agent or one logical change per PR.
- ✂️ Small, focused commits with clear messages.
- 🟢 CI must pass. GitHub Actions validate agents on every PR and merge, here and in each agent's repo.
- 👍 At least one maintainer approval is required. Safety review is required for any new agent or any change to data handling, prompts or content rules.
- 🙊 Do not merge your own PR.

---

## 🛂 10. Review and listing

- 🧒 New agents go through community safety review covering age suitability, data collection and fairness before they are listed in the marketplace.
- 🔀 Merging code to `main` is not the same as marketplace approval.
- 🛑 Agents found unsafe after listing can be delisted immediately, pending a fix.
- 🏛️ The founding set of agents is maintained by the maavaDao team. Community contributions to them and new community agents follow the workflow above.

---

## 📜 11. Licensing and rewards

- 🪪 All code is licensed under Apache-2.0. By contributing, you agree your work is released under it.
- 🏅 Contributors keep credit for their work. Authors are recorded in `agent.yaml` and in the repo history.
- 💸 Revenue sharing (60% to the developer community, 40% to Maava Charity for children's education) is handled by the maava platform, not by this repo. Never add payment logic, fees, paywalls or commissions to an agent here.
- 🚫 Do not claim, imply or promise earnings to contributors or users.

---

## 🤖 12. Rules for AI coding assistants

If an AI tool is working in this repo on someone's behalf, it must also:

- 📚 Read this file, `CONTRIBUTING.md` and the target agent's `agent.yaml` before changing anything.
- 🎯 Stay inside the scope of the request. No drive-by refactors, and no edits to unrelated agents.
- 🚫 Never invent data, sources, licences, test results or reviewer approvals.
- 🔐 Never commit secrets, and never weaken safeguarding, privacy or content-filtering behaviour to make a test pass.
- ⚙️ Never edit generated files such as `index.json` or the README's table of agents.
- 🙋 Flag anything uncertain for a human to decide, especially safety, data handling and anything involving children.
- 🗒️ Tell the human what it changed and what it did not verify.

---

## 💛 13. Conduct

- 🤗 Be kind, respectful and patient. This community includes first-time contributors, teachers and students.
- 🚫 No harassment, discrimination or personal attacks.
- 💡 Disagree about code, not people.
- 🚨 Raise concerns about child safety immediately and directly to the maintainers.

---

## 🗳️ 14. Changing these rules

Platform-wide standards and responsible AI policy are set by the community through maavaDao governance. Proposals to change this file follow the normal pull request process and need maintainer approval. Changes to safeguarding rules also need a safety reviewer's approval.
